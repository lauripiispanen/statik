### 11.8 SCIP cross-file refs in FileGraph (M)
**Complexity**: M
**Prerequisites**: 11.7
**Files**: `src/cli/graph_builder.rs`, `src/model/file_graph.rs`, `src/db/mod.rs`

**The problem**: SCIP enrichment adds 368 cross-file call references to the
`refs` table, but no analysis command uses them. All file-level analyses
(dead-code, impact, cycles, deps, lint) are driven by `FileGraph`, which
is built exclusively from the `imports` table (tree-sitter `use`/`import`
statements). SCIP data only affects confidence scores today.

**Evidence** (dogfooding on statik itself):
- SCIP added 216 cross-file refs and 46 unique cross-file edges
- All analyses produced identical output before vs after enrichment
- The refs table has the data; FileGraph just doesn't read it

**The fix**: Augment `build_file_graph()` in `graph_builder.rs` to query
cross-file SCIP refs from the `refs` table and add supplemental edges.

**Design decisions**:
1. SCIP-derived edges supplement import edges, they don't replace them
2. Add `is_scip_derived: bool` to `FileImport` so output can annotate them
3. Only add edges not already covered by an import edge (dedup)
4. These edges inherit the SCIP confidence level (Certain when fresh)

**Implementation**:

Tasks:
- [x] Add DB query: cross-file SCIP refs grouped by (source_file, target_file)
  `SELECT DISTINCT r.file_id, s.file_id FROM refs r JOIN symbols s ON
  r.target_id = s.id WHERE r.source = 'scip' AND r.file_id != s.file_id`
- [x] Add `is_scip_derived: bool` field to `FileImport` (default false)
- [x] In `build_file_graph()`, after import resolution, add SCIP-derived
  edges for pairs not already covered by import edges
- [x] Update output formatters to optionally annotate SCIP-derived edges
  (`[scip]` marker in text output, `"is_scip_derived": true` in JSON)
- [x] Test: after enrichment, `deps` shows SCIP-discovered edges that
  import parsing missed
- [x] Test: `impact` blast radius includes files connected via SCIP refs
- [x] Dogfood: compare dead-code/impact/cycles before and after on statik

**What this unlocks** (automatic benefits, no extra code):
- `dead-code`: fewer false positives (files reachable via SCIP calls)
- `impact`: more complete blast radius
- `cycles`: discovers hidden cycles from implicit dependencies
- `deps`: shows call-based dependencies alongside import-based
- `lint`: architectural rules catch SCIP-discovered violations
- `who`/`bus-factor`: more accurate impact radius for reviewer suggestion

**Acceptance**: After enriching statik with rust-analyzer SCIP, at least
some analyses show different (improved) results compared to tree-sitter
only. The SCIP-derived edges are visible in `deps` output.
