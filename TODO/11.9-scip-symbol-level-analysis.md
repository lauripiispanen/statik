### 11.9 SCIP-powered symbol-level analysis (L)
**Complexity**: L
**Prerequisites**: 11.8, 4.5
**Files**: `src/analysis/dead_code.rs`, `src/analysis/impact.rs`, `src/cli/commands.rs`, `src/model/graph.rs`

**The opportunity**: SCIP provides precise symbol-to-symbol cross-file
references. 11.8 collapses these to file-level edges for FileGraph. This
task uses the full symbol-level precision to enable analyses that no other
CLI tool offers.

**Why this matters**: Tree-sitter's `SymbolGraph` is mostly intra-file refs
(5,240 refs, all within the same file for statik). SCIP adds cross-file
refs that make symbol-level analysis tractable. Without SCIP, asking "who
calls this function" can only be answered within a single file. With SCIP,
it works across the entire project.

**What this enables**:

1. **Symbol-level impact**: `statik impact --symbol FileGraph::imported_by`
   → "8 specific call sites in 5 files" instead of "29 files depend on
   file_graph.rs". Precise blast radius for method-level changes.

2. **Symbol-level dead code improvements**: Augment `detect_dead_symbols()`
   entry point seeding with SCIP cross-file ref targets. Currently the
   Linker (`link_cross_file_symbols()`) only uses import/export matching
   (tree-sitter). SCIP cross-file call refs should seed the BFS so that
   symbols called from other files are not falsely reported as dead.

3. **Cross-file callers**: `statik callers MyStruct::new` finds call sites
   across all files, not just within the defining file. The `SymbolGraph`
   already loads SCIP refs via `all_references()`, but the Linker-based
   cross-file seeding misses SCIP-only edges.

4. **Cross-file references**: Same as callers but for all ref kinds (not
   just calls). Annotate SCIP-sourced refs with `source: "scip"` in output.

**Implementation approach**:

Phase A — Fix symbol-level dead code seeding (S):
- [ ] In `detect_dead_symbols()`, after building `linker_targets`, scan
  `SymbolGraph` for cross-file refs where source file != target file
- [ ] Add those target symbols to the seed set
- [ ] Test: symbol that is only reachable via SCIP cross-file ref is NOT
  reported as dead

Phase B — Symbol-level impact command (M):
- [ ] Add `--symbol <name>` flag to `statik impact`
- [ ] When `--symbol` is provided, use `SymbolGraph` BFS from the target
  symbol instead of `FileGraph` BFS from the file
- [ ] Output: list of (file, symbol, ref_kind, line) tuples showing
  exactly which symbols in which files would be affected
- [ ] Falls back to file-level when no SCIP data available (with warning)

Phase C — Annotate refs/callers output (S):
- [ ] Add `source` column to `all_references()` DB query
- [ ] Show `[scip]` / `[tree-sitter]` marker in text output
- [ ] Add `"source"` field to JSON output

**Acceptance**: `statik impact --symbol X` shows precise symbol-level blast
radius when SCIP data is available. `statik dead-code --scope symbols`
has fewer false positives after SCIP enrichment. `statik callers X` finds
cross-file call sites.

**Relationship to Phase 4**: Phase 4 (DONE.md) delivered the SymbolGraph
infrastructure, `symbols`/`references`/`callers` commands, and symbol-level
dead code. This task activates their full potential by feeding them SCIP
cross-file data. It's "Phase 4 powered by SCIP" rather than a new phase.
